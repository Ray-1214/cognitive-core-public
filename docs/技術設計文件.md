## 2. 目標與非目標

### 2.1 目標

| # | 目標 | 對應計畫書 | 驗收方式 |
| --- | --- | --- | --- |
| G1 | 高歧義語句的語意一致性優於 Zero-shot baseline | §5.1 | BERTScore + 自我一致性分數 |
| G2 | Router 能有效分流，慢速通道只在需要時啟動 | RQ2 | 分流準確率 + 平均成本下降幅度 |
| G3 | 系統能明確回報自身不確定性 | §4.3 | 錨點 `UNKNOWN` 欄位 + 澄清提問 |
| G4 | 多輪對話不因長文本而遺失上下文 | RQ3 | Lost-in-the-Middle 測試 |
| G5 | 支援多 provider（含校內地端），可做跨模型對比 | 差異項 | 換 config 即可切換 |
| G6 | 輸出格式穩定 | §4.7 | Schema 驗證通過率 ≥ 99% |
| G7 | 目標語言可擴充，新增語言不需改程式碼 | 延伸 | 新增 skill 檔即可跑通 |

### 2.2 非目標

- ❌ 不做模型訓練 / fine-tune
- ❌ 不追求 BLEU 的 SOTA（我們比語意穩定性，不比譯文流暢度）
- ❌ 不做生產級服務（無帳號、無多租戶、無 SLA）
- ❌ 不處理語音、圖片
- ❌ 不做低延遲（本系統以算力換精確度，見 §2.3）

### 2.3 關於「改善只是因為算力多」

系統立場：**用可控的額外算力換語意穩定性**，這在高風險場景是划算的交易。

但論文上仍需誠實呈現，做法是報告成本並加一組**等算力 baseline**：

| 組別 | 說明 | 推論次數 |
| --- | --- | --- |
| B0 | 單次直翻（計畫書的 Zero-shot 對照組） | 1× |
| B1 | 鏈式往返翻譯 | K× |
| B2(N) | 等算力 self-consistency，N=1..10，medoid 選擇 | N× |
| **E1** | **本系統（Router + 多視角 + 反思）** | **實測** |

B2 不是單一組，而是**掃描 N 畫出成本–準確度曲線**，E1 是曲線上的一個點；E1 落在曲線上方才算贏。詳細定義見 §7.2——**這是全篇的勝負手**。

### 3.2 LangGraph 狀態機（計畫書指定）

計畫書 §6 明列「LangGraph 狀態機設計」為需教授指導的項目，因此必須實際用上。

class GraphState(TypedDict):

節點與邊：

```

               └─(slow)─→ build_anchor → translate_multi │

## 4. 核心模組設計

### 4.1 模組一：自適應語意路由器（RQ2）

**計畫書原方案的問題**：用「跨語言 PPL 變異數」當路由訊號會造成循環——要算變異數就得先做多路徑回譯，而多路徑回譯正是慢速通道本身，快慢分流就失去意義。

**修正方案**：改用便宜的前置訊號路由；跨語言 PPL 變異數保留，但移到慢速通道內當**事後驗證指標**。

| 訊號 | 實作 | 成本 | 偵測的歧義類型（計畫書 §3.5） |
| --- | --- | --- | --- |
| S1 歧義詞典命中 | 自建中文多義詞 / 成語 / 委婉語詞表 | 極低 | 詞彙歧義 |
| S2 主詞省略偵測 | 規則 + CKIP / spaCy 依存句法 | 低 | 指代歧義 |
| S3 句法複雜度 | 句長、從句數、標點密度 | 極低 | 句法歧義 |
| S4 文化專有項 | 成語 / 流行語 / 典故詞表 | 極低 | 語用歧義 |
| S5 LLM 快速判定 | 單次小模型呼叫，只回歧義分數 | 中 | 綜合 |

$$
\text{AmbiguityScore} = \sum_{i=1}^{5} w_i \cdot S_i, \qquad
\text{path} = \begin{cases} \text{fast} & \text{if Score} < \tau \\ \text{slow} & \text{otherwise} \end{cases}
$$

**權重不擬合。** 既然主指標是 AUC，改報「每個訊號各自的 AUC」＋「未加權總和的 AUC」——dev/test 洩漏風險降到零，dev-30 也不必撐起 6 個參數的擬合。需要擬合版本時在 CAD-100 上做交叉驗證，**兩個都報**。

**RQ2 的答案就在這裡**——論文要報告的是「分流準確率」與「相對於全走慢速通道的成本下降幅度」，這是計畫書承諾要回答的問題。

### 4.2 模組二：多視角驗證代理人（＝演算法 1）

**完全依照計畫書演算法 1 實作**，日語 + 英語作為驗證錨點（理由見計畫書 §4.4 語法強制顯性化原則）：

```
T_en ← Translate(T_src, English)      ┐
T_jp ← Translate(T_src, Japanese)     │ 平行
V_en ← BackTranslate(T_en, Chinese)   │
V_jp ← BackTranslate(T_jp, Chinese)   ┘
Score ← CosineSimilarity(Embed(V_en), Embed(V_jp))

if Score < τ:
    Details  ← IdentifyDiff(V_en, V_jp)
    T_final  ← ReflectionAgent(T_src, Details)   ← §4.3 填這個留白
else:
    T_final  ← T_en
```

架構上驗證語言不寫死為兩種（G7），但**預設與論文主實驗都用日英兩語**，與計畫書一致。

#### 4.2.1 偵測與診斷分離（§8.5 後的架構調整）⭐

演算法 1 的多視角比對其實承擔**兩件不同的工作**：

| 工作 | 用途 | 單探針能否勝任 |
| --- | --- | :-: |
| `Score` | 觸發偵測——這句要不要走慢速通道 | ✅ 可以（往返保真度即可給分數） |
| `IdentifyDiff` | 餵給反思——差異**在哪裡** | ❌ 不行（單一譯本無從比對出差異點） |

§8.5 的數據只挑戰前者，**完全沒有碰到後者**。兩者可以分離：

```
單探針往返保真度  ──▶ 偵測器（便宜，每句都跑）
                        │ 超過閾值
                        ▼
多視角平行翻譯    ──▶ 診斷器（貴，只在慢速通道跑）
                        │
                        ▼
                   IdentifyDiff → 反思
```

**這比原設計更好**：原設計把最貴的操作（多視角平行翻譯）放在偵測階段，等於每句都付診斷成本。改成分離後更貼合 §4.2 的快慢分流哲學，**直接強化 RQ2**。

實作上不需要新程式碼——驗證語言集本來就是 config（G7），「跨語言 en+ja」「同語言 en+en」「單探針 ja」是**同一條路徑的三個 config**。因此 §4.4 從「架構承諾」變成「實驗結果」，論文上是升級而非降級。評測面只需在 §7.2 加一組 E1-d 單探針消融。

> 計畫書承諾的是 E1 被實作並評測，不是 E1 必須贏；§5.1 的預期比較對象是 B0 而非單探針。**合約未破。**

### 4.3 模組三之前：反思代理人與語意錨點文件

> 📌 **這是計畫書 `ReflectionAgent()` 的實作，不是新主軸。**
> 計畫書 §4.3 承諾系統要「重新分析歧義來源」「生成多個可能的語意解釋並標示其適用情境」「回傳澄清提示」——本節就是那三件事的資料結構。

反思被觸發時，把原文的隱含資訊展開成一份**語意錨點文件**，然後從錨點重新翻譯（而非從上一輪譯文重翻）。

```yaml
# ── 不可變區（原文永遠在最上面）──────────────
source:
  text: "方便的話明天再說吧"
  language: zh-TW

# ── 顯性化區 ────────────────────────────────
explicit:
  agent:      { value: UNKNOWN, note: "原文省略主詞" }
  patient:    { value: "聽話者", confidence: 0.8 }
  action:     "推遲討論此事至明天"
  time:       { reference: "明天", tense: FUTURE }
  register:   SEMI_FORMAL
  social_relation: { value: UNKNOWN, note: "影響日文敬語選擇" }
  cultural_items:
    - term: "方便"
      literal: "convenient"
      actual_sense: "委婉推託"
      ambiguity_type: PRAGMATIC       # 對應計畫書 §3.5 歧義分類
  # 註：speaker_intent 不在此層——§8.2 實證模型幾乎不會對它填 UNKNOWN（7.2%），
  #     單值欄位會逼出過度自信的斷言。已降層至各 reading 內部。

# ── 不確定性區（＝計畫書 §4.3）──────────────
uncertainty:
  unknown_fields: [agent, social_relation]   # 僅適用純量欄位
  ambiguity_score: 0.72
  text_determinable: false            # 原文本身能否決定用哪個讀法
  alternative_readings:               # 計畫書：「生成多個可能的語意解釋」【必填】
    - reading: "委婉拒絕"
      speaker_intent: SOFT_REFUSAL    # ← intent 降層於此，每個讀法各有其意圖
      licensed_when: "對方為平輩或下屬，且無先前約定"
    - reading: "字面詢問時間"
      speaker_intent: INQUIRY
      licensed_when: "先前已約定討論此事"
  clarification_questions:            # 計畫書：「回傳澄清提示」
    - "這句話是對上司、同事還是朋友說的？"

provenance:
  built_by: "<role: reflect>"
  revisions: 2
```

**四條約束**：

1. `source.text` 任何階段不得修改
2. 反思後的重譯只讀錨點，**不讀上一輪譯文**（避免誤差累積）
3. `UNKNOWN` 是合法且被鼓勵的值——猜錯比留白有害
4. ⭐ **意圖類資訊一律走 `alternative_readings` 列舉，不設單值欄位**

> 📌 **約束 4 的依據（§8.2 + §8.3 兩次獨立實證）**：
> 承認 UNKNOWN 是**自我評估**任務，模型抗拒（意圖欄位僅 7.2% 標對，LLM 判意圖異同 AUC 0.500）；
> 列舉讀法是**生成**任務，模型樂意。
> **修法不是說服模型誠實，而是改變輸出結構，讓誠實不需要自我否定。**

**不確定性感知（計畫書 §4.3）的實作**：`text_determinable == false`、`unknown_fields` 非空、或 `revisions` 達上限 R 仍未收斂 → 進入高不確定性狀態 → 輸出改為「多個讀法 + 適用情境」或回傳澄清提問，而非單一譯文。

⚠️ **反向失效模式**：§8.4 指出模型被要求列舉多重意義時會**過度生成**。因此評測必須同時量 Recall 與 **Precision**（§7.6），只量「正確讀法有沒有出現」會得到假的漂亮數字。上限機制見 Open Q N。

> ⚠️ **Open Q A**：錨點欄位要幾個？太多小模型填不動、成本高。傾向分「核心 6 欄（agent / time / register / social_relation / intent / cultural_items）」＋「延伸欄位」兩層，先做核心。

### 4.4 模組三：動態記憶模組（RQ3）

計畫書指定 **ChromaDB + 滾動式摘要（Rolling Summary）**，照做。

- **儲存**：對話歷史向量化存入 ChromaDB；若該輪產生過錨點文件，錨點一併存（資訊密度高於原始訊息）
- **檢索**：餘弦相似度（計畫書公式 3）
- **滾動摘要**：超過視窗長度時，舊訊息壓縮為摘要；有錨點的優先摘要 `explicit` 區塊
- **滑動視窗**：計畫書 RQ3 明列，保留

**RQ3 的驗收**：做一組 Lost-in-the-Middle 測試——把關鍵資訊分別放在長對話的頭 / 中 / 尾，測系統的召回率。有無記憶模組的對照曲線就是論文的圖。

後端為 vLLM + LiteLLM（由 `system_fingerprint` 可見）。

**能力矩陣**：

| 模型 | 基本 chat | `json_object` | `json_schema` (strict) | 備註 |
| --- | :-: | :-: | :-: | --- |
| `mistral-small-4` | ✅ | ✅ 33 tok | 🔴 **失效** | 卡在輸出空白直到耗盡 token；800 / 2000 皆同，缺必填欄位 |
| `gpt-oss-120b` | ✅ | ✅ | ✅ 48 tok | |
| `llama4scout` | ✅ | ✅ | ✅ 51 tok | |
| `nemotron-3-ultra` | ✅ | — | — | 推理模型，內容在 `reasoning_content`，回「OK」耗 273 tok |
| `ornith-35b` | ✅ | — | — | 同上，耗 202 tok |
| `diffusiongemma-26b` | ✅ | — | — | **不接受** `temperature` / `seed` / `logit_bias` 等取樣參數 |

**三項對設計的直接影響**：

1. 🔴 **主力模型的嚴格結構化輸出不可用** → §5.2 必須設計降級階梯，且**不得假設 `json_schema` 可用**
2. ✅ **`bge-m3-embedding` 在校內 API 上** → Open Q E 解決，不需本地 torch（本機 Python 3.14 尚無 torch wheel，這條風險同時消失）
3. ✅ **校內有 6 個 LLM** → M8 跨模型對比可完全在校內完成，付費 API 非必要
4. ⚠️ 推理模型與 diffusion 模型的參數不相容 → provider 層需 per-model 能力旗標，不能一套參數打天下

### 5.1 Provider 抽象層

計畫書原寫 Ollama + 本地 GGUF，改為多 provider。**論述不受影響**：校內 LLM 端點是地端服務，「不依賴商用雲端、機構內部署」的隱私論述依然成立，只是從「單機 GPU」變成「校內地端」。

class LLMProvider(Protocol):

        messages: list[Message],

        temperature: float | None = 0.0,

```

### 5.2 結構化輸出（計畫書 §4.7）

⚠️ §5.0 實測顯示**主力模型的 `json_schema` 是壞的**，因此不能把結構化輸出交給單一機制。設計為**降級階梯**，每一級都由 client 端 Pydantic 做最終驗證：

```
① json_schema（僅 capabilities.json_schema == true 的模型）
      │ 失敗 / 不支援
      ▼
② json_object + prompt 內描述 schema      ← mistral-small-4 走這條，實測 33 tok 穩定
      │ 失敗
      ▼
③ 純 prompt + 剝除 markdown 圍欄後寬鬆解析
      │ 失敗
      ▼
④ 重試 N 次（temperature 微調）→ 仍失敗則標記 schema_violation 並記錄原始輸出
```

**不論走哪一級，最終都必須通過 Pydantic 驗證才算成功**——`json_schema` 能過不代表欄位語意正確（實測中它連必填欄位都會漏）。

Schema 通過率（G6）按「級別」分別統計：走到第幾級、各級成功率各多少。這份數據本身就是論文可寫的內容——**「地端部署的開源模型，其結構化輸出可靠度差異極大」是個對實務有價值的發現**。

推理模型（`reasoning: true`）需另外處理：內容在 `reasoning_content` 而非 `content`，且 `max_tokens` 要放大數倍。`diffusiongemma-26b` 需剝除所有取樣參數。這些由 adapter 依 `capabilities` 自動處理。

### 5.3 語言技能檔（Language Skill）

每語言一檔 `skills/<code>.md`，新增語言零程式碼改動（G7）。內容：

- **強制顯性化欄位**：翻到本語言時哪些錨點欄位不得為 UNKNOWN
- **翻譯陷阱**：如中文「你」不可直譯日文「あなた」
- **回譯檢查點**：回譯成中文時要確認哪些資訊未遺失
- **Few-shot 範例**：正確譯文 vs 常見錯譯 + 錯在哪
- **輸出格式約束**：不得加注音、不得加解釋括號

> ⚠️ **Open Q B**：skill 檔整份塞 prompt（簡單、吃 token）還是依錨點動態挑段落？傾向先整份塞，量測成本後再優化。

### 5.4 實驗基礎設施 ⭐

**這是研究專案最容易忽略、但決定論文能不能寫完的部分。** 建議在 M0 就做好：

| 元件 | 作用 | 為什麼重要 |
| --- | --- | --- |
| **呼叫快取** | `hash(provider, model, prompt, temperature, n, seed, 其餘 params)` → 回應，存 SQLite。⚠️ **鍵必須含 `temperature` / `n` / `seed`**——校內端點本身會快取相同請求（§8.5），本地快取若漏掉取樣參數會複製同一個陷阱，讓 `n=k` 重取樣靜默失效 | 評測會大量重複呼叫。快取讓重跑幾乎免費，且**讓實驗可重現** |
| **Run 記錄** | 每次執行存一筆完整記錄：所有中間步驟、token 用量、耗時、config snapshot（**必含 git commit hash 與 dirty 旗標**）、prompt hash | 寫論文時要什麼數據都能回頭撈，不用重跑；commit hash 讓任一筆數據都能還原出當時的程式碼 |

| **成本儀表板** | 即時顯示 token / 呼叫次數 / 估計費用 | 用付費 API 做對比實驗時的煞車 |
| **可重現性封包** | 一鍵匯出「config + 資料 + 結果 + 版本」 | 開源與投稿要求 |

固定 `temperature=0`、記錄 model 版本字串、config 存進每筆 run。

## 6. Web 介面（Vite + React SPA + FastAPI）

計畫書 §4.9 寫 Streamlit。**改為瀏覽器 SPA 而非 Electron**——計畫書自己說介面是「研究驗證與除錯工具，而非最終產品」，包成桌面應用不符合這個定位，還會多出打包、簽章、跨平台等與研究無關的工作。純瀏覽器 SPA 的 SSE 時間軸與 Electron 完全一樣，而且**讓 D6 差異降到零**（同樣是「跑在本機的網頁介面」，與計畫書的 Streamlit 定位一致）。

計畫書對介面的三項實質要求，全部保留：

1. 左側原始對話視窗
2. 右側**決策摘要**（判斷依據 + 信心分數）
3. **不直接揭露原始 Chain-of-Thought**（AI 安全與隱私倫理）

### 6.1 架構

```
  瀏覽器 (localhost:5173)
    Vite + React SPA
        │  HTTP / SSE
        ▼
  uvicorn (FastAPI, 127.0.0.1:8000)  ← 只綁 loopback，不對外
        │
    cognitive_core
```

- 開發：`uvicorn` 與 `vite dev` 兩個行程，Vite proxy 轉發 `/api`
- 展示：`npm run build` 後由 FastAPI 直接托靜態檔，只需起一個行程
- **SSE 串流**：LangGraph 的 `astream_events` → FastAPI SSE → 前端即時渲染

⚠️ 推理模型（`nemotron-3-ultra` / `ornith-35b`）的 `reasoning_content` **不得推送到前端**——那正是計畫書禁止揭露的原始 CoT。SSE 事件在後端就要濾掉該欄位。

### 6.2 介面設計建議

右側決策摘要用**時間軸**呈現，每個節點可展開：

```
① Router      歧義分數 0.72 → 慢速通道
              觸發訊號：詞彙「方便」命中委婉語詞表、主詞省略
② 平行翻譯     日文 ✓  英文 ✓
③ 回譯比對     餘弦相似度 0.61 ＜ 閾值 0.75  ⚠ 不一致
④ 反思 (1/3)   差異定位：social_relation 欄位缺失
⑤ 重新翻譯     日文 ✓  英文 ✓
⑥ 回譯比對     餘弦相似度 0.88  ✓ 通過
⑦ 不確定性     ⚠ agent 欄位仍為 UNKNOWN
              → 澄清提問：「這句是對上司還是朋友說的？」
─────────────────────────────────
成本：6 次呼叫 / 3,240 tokens / 4.2 秒
```

**倫理界線的實作**：時間軸顯示的是**結構化的決策記錄**（哪個訊號觸發、哪個欄位缺失、相似度多少），不是模型的原始推理文字。這正好符合計畫書「不直接揭露原始 CoT」的要求，而且比揭露 CoT 更好懂。Demo 時這個時間軸會是最有說服力的畫面。

## 7. 評測設計

### 7.1 資料集分工 — CAD-100 完整保留為 test

**不切分 CAD-100。** 計畫書 §4.1 承諾的是「100 句」的測試集，切成 dev/test 會變成「70 句測試集」，得額外解釋；而且在測試集上調過參再報成效，是審查一定會打的方法論瑕疵。

| 資料集 | 句數 | 用途 | 可否反覆查看 |
| --- | --- | --- | --- |
| **dev-30** | 30（另造） | 調 τ 閾值、Router 權重 $w_i$、prompt 迭代 | ✅ 隨便看 |
| **CAD-100** | 100（計畫書承諾） | **最終評測，只跑一次** | ❌ 封存 |
| WMT23 子集 | 200–500 | 一般文本不退步的佐證 | ✅ |

**分層配比（先寫死，兩個資料集共用）**：§8.2 已證明模型表現隨歧義類型而異，測試集必須能分型報告，否則整體平均會掩蓋掉真正的失效點。

| 歧義類型 | CAD-100 | dev-30 | 下限 |
| --- | :-: | :-: | :-: |
| 詞彙 LEXICAL | 30 | 9 | ≥25（CAD-100） |
| 指代 REFERENTIAL | 30 | 9 | ≥25 |
| 語用 PRAGMATIC | 40 | 12 | ≥25 |

dev-30 與 CAD-100 同配比但**句子完全不重疊**，否則調出來的參數搬不過去。

**60 句蒐集來源改用現成資料集**（不自行蒐集，省時且來源可追溯）：CHAmbi、DEBATE、Wu et al. 2025 的公開資料（見 §8.4，**各自授權需逐一確認方可使用**）。

自造 40 句照舊，補現成資料集蓋不到的**台灣在地語用**（如「意思意思」「方便」的委婉用法）。**CAD-100 的「自建」性質不受影響——自建的是標註層，那才是本研究的貢獻所在**，句子來源為何不影響這一點，但論文須如實說明來源組成。

⚠️ **紀律**：所有閾值、權重、prompt 都只能在 dev-30 上調。CAD-100 跑第一次的結果就是論文數字；若因故重跑，必須在論文誠實揭露跑了幾次。

### 7.2 對照組 — B2 是全篇勝負手

「改善只是因為算力多」這個質疑，成敗全看 B2 設計得好不好。原本只寫「等算力 self-consistency」，但**自由文本沒有「取多數」這種東西**，必須明確定義。

**取多數 → 取 medoid**：N 個候選譯文兩兩算語意相似度，選出「到其他所有候選的距離總和最小」的那一個：

$$
\hat{y} = \arg\min_{y_i \in Y} \sum_{y_j \in Y,\, j \neq i} \bigl(1 - \cos(\text{Embed}(y_i), \text{Embed}(y_j))\bigr)
$$

**等算力 → 掃描 N，畫成本–準確度曲線**：不要只比一個點。讓 B2 跑 $N = 1, 2, \dots, 10$，每個 N 得到一組（成本, 準確度），連成曲線；E1 是曲線圖上的**一個點**。

- E1 落在曲線**上方** → 相同算力下本架構更準，改善來自結構
- E1 落在曲線**上** → 本架構只是換個方式花算力，論文要誠實寫

| 組別 | 說明 | 成本 |
| --- | --- | --- |
| B0 | Zero-shot 單次直翻（計畫書指定對照組） | 1× |
| B1 | 鏈式往返翻譯（漂移對照，§7.7） | K× |
| **B2(N)** | **self-consistency，N=1..10，medoid 選擇** | **N×** |
| E1 | 本系統完整流程 | 實測 |
| E1-a | 消融：關閉反思 | |
| E1-b | 消融：關閉 Router（全走慢速） | |
| E1-c | 消融：關閉記憶模組 | |
| **E1-d** | **消融：單探針偵測（§4.2.1）**——偵測改用單一語言往返保真度，多視角僅在慢速通道當診斷器 | 低 |

> 💡 這張成本–準確度曲線**同時就是 RQ2 的散點圖**（Router 的價值＝在同一張圖上把 E1 往左推）。原本規劃的兩張圖合併成一張，少做一張圖還更有說服力。

### 7.3 指標 — 分清楚哪個資料集能算哪個

**BERTScore 在 CAD-100 上算不出來**：§7.6 決定不做標準譯文，沒有 reference 就沒有 BERTScore。硬要算就得回頭做標準譯文，而多義句本來就沒有唯一正解。

| 指標 | 資料集 | 宣稱 | 需標註 |
| --- | --- | --- | --- |
| **正確義項命中率** ⭐ | CAD-100 | **主指標**：系統是否選對義項 | ✅ §7.6 |
| UNKNOWN 準確率 | CAD-100 | 該留白時有沒有亂猜 | ✅ §7.6 |
| 歧義捕捉率 | CAD-100 | 錨點是否抓到歧義點 | ✅ §7.6 |
| Router 分流準確率 | CAD-100 | RQ2 | ✅ §7.6 |
| **BERTScore** | **WMT23 子集** | **「一般文本不退步」**（非「更好」） | 有現成 reference |
| 留出語言一致性 | CAD-100 | 非循環的語意保留證據（見下） | 否 |
| 收斂診斷 | 全部 | 反思迴圈行為分析，**非成效指標** | 否 |
| 成本（calls / tokens / 秒） | 全部 | 誠實揭露算力代價 | 否 |
| Schema 通過率（分級） | 全部 | G6 + §5.2 的實務發現 | 否 |

**自我一致性分數的循環論證問題**：反思迴圈的終止條件就是「en/ja 回譯一致性 ≥ τ」，所以 E1 的一致性高是**建構出來的**，拿它比 E1 vs B0 是套套邏輯。兩項修正：

1. **降級為收斂診斷指標**——只用來回答「迴圈平均幾輪收斂、多少比例撞上上限 R」，不當成效證據
2. **另設留出語言**（de，全程不進迴圈、不參與終止判斷）——`錨點 → de → 回譯中文`，與**原文**算相似度。因為迴圈從未針對 de 最佳化，這個數字是非循環的語意保留證據

計畫書公式 (5) 仍需重新定義（`Var({V_en, V_jp, V_es})` 對向量集合未定義，且 `V_es` 與只用日英矛盾）。收斂診斷用平均成對餘弦距離：

$$
\text{Score}_{consistency} = 1 - \frac{2}{k(k-1)}\sum_{i<j}\bigl(1 - \cos(V_i, V_j)\bigr)
$$

### 7.4 統計檢定 — n=100 不做信賴區間，「顯著優於」是空話

CAD-100 只有 100 句，兩組差幾個百分點很可能是雜訊。**必做成對拔靴法（paired bootstrap）**：

1. 對 100 句**成對**重抽樣（同一句在兩組取同一個抽樣索引，消除句子難度的變異）
2. 重複 B = 10,000 次，每次計算 $\Delta = \text{metric}(E1) - \text{metric}(B0)$
3. 報告 $\Delta$ 的 95% 信賴區間與 $p$ 值

**若 CI 跨越 0，就不能寫「顯著優於」**，要誠實寫成「觀察到提升但未達統計顯著，受限於 n=100」。多組比較（B2 的 10 個 N × 多個 profile）需做 Holm–Bonferroni 校正。

### 7.5 人類評測（計畫書 §5.3）

計畫書指定的照做：3 位中英日三語評測員、CAD-100 抽 30 句、Likert 1–5 評「語意精確度」與「文化得體性」、**Fleiss' Kappa**。

**三項補強**（其中兩項現在不定就補不回來）：

1. **同時報 Krippendorff's α (ordinal)**
   Fleiss' Kappa 把 Likert 當名目尺度，評 4 vs 5 和評 1 vs 5 都算「不一致」，在順序尺度上會**系統性低估**一致性。照計畫書要求報 Kappa，但同時報 α (ordinal) 並說明差異來源。這是補強不是取代，不算差異項。

2. 🔴 **盲測** — 事後補不回來
   評測員不得知道哪個譯文出自本系統、哪個出自 baseline。組別標籤在給人看之前就要移除。

3. 🔴 **樣本順序隨機化** — 事後補不回來
   每位評測員拿到的句子順序、以及同一句內各組譯文的排列，都要獨立隨機化，避免順序效應與疲勞效應。隨機種子要記錄。

4. **先做 pilot**：正式評測前拿 5 句（不屬於那 30 句）三人先評一輪、對齊標準。若 pilot 的一致性太低，先改評分準則再開始，否則 30 句評完才發現沒共識就得重來。

**LLM-as-a-Judge 的客觀性**（計畫書 §6 明列為需教授指導的項目）：模型有 self-preference bias，會偏好自己家的輸出。用 `judge_cross` profile——受測模型在校內 API，裁判用 Gemini（不同廠商、不同訓練資料）。並以人類評測的 30 句作為錨點，報告 LLM judge 與人類評分的相關係數；相關性低就不採信 LLM judge 的結論。

### 7.6 CAD-100 標註方案

不做「標準譯文」（多義句本無唯一正解，成本又高），改做**歧義點標註**。

⚠️ **schema 必須在標註開工前定案**——初版的 `correct_reading` / `wrong_reading` 有兩個致命缺陷：**(1)** 預設每句有唯一正解，與 `alternative_readings`「多讀法並存」的前提直接矛盾；**(2)** 沒有任何欄位能量測 §8.4 警告的**過度生成**。現在不改，100 句要重標。

```yaml
- id: cad-001
  text: "方便的話明天再說吧"
  origin: self_authored          # self_authored | chambi | debate | wu2025
  ambiguity_type: PRAGMATIC      # 計畫書 §3.5 分類，供分層報告
  expected_route: slow           # ← Router 的 ground truth

  # 所有「原文允許」的讀法。多讀法並存是常態，不預設唯一正解。
  licensed_readings:
    - reading: "委婉推託，實際不想談"
      licensed_when: "無先前約定，且說話者處於可迴避的位置"
    - reading: "字面詢問對方明天是否有空"
      licensed_when: "先前已約定討論此事"

  # 原文本身能否決定用哪個讀法。false ⇒ 系統應保留多讀法或提問，不得擅自擇一。
  text_determinable: false

  # ⭐ 逐欄位的可判定性 —— §8.2 的量測缺陷所逼出的必要欄位。
  #    句子層級的 text_determinable 不夠：一個語意明確的句子，
  #    仍可能有某些錨點欄位無從判定（如無受話者時的 social_relation）。
  #    沒有這欄，UNKNOWN 的 precision 就算不準。
  field_determinable:
    agent: false            # 「方便的話…」誰再說，原文未定
    tense: true             # 「明天」→ FUTURE
    register: true
    social_relation: false  # 無稱謂線索
    speaker_intent: false   # 推託或詢問，取決於前文

  # ⭐ 量 precision 用：看似合理但原文並不支持的讀法。
  #    沒有這欄就只能算 recall，會得到假的漂亮數字（§8.4）。
  spurious_readings:
    - "承諾明天一定會給答覆"      # 原文無承諾語意
    - "詢問對方是否身體不適"      # 「方便」的另一義，此語境不成立

  required_clarifications: [social_relation]
  annotator: human_primary
  ai_drafted: true               # ← 誠實記錄，見下
```

**評分方式**（三項並報，缺一不可）：

| 指標 | 算法 | 防的是什麼 |
| --- | --- | --- |
| **Recall** | 系統列出的讀法涵蓋多少 `licensed_readings` | 漏讀 |
| **Precision** ⭐ | 系統列出的讀法有多少落在 `spurious_readings`（或無中生有） | **過度生成**（§8.4） |
| **Determinability 準確率** | 系統對 `text_determinable` 的判斷是否正確 | 該保留多讀法時擅自擇一 |

只報 Recall 是無效評測——把所有可能讀法都列出來即可拿滿分。**Precision 才是修法有沒有用的證據。**

一句約 2–3 分鐘。這份標註**一魚五吃**：Recall、Precision、Determinability、歧義捕捉率、Router 分流準確率全靠它。

**標註流程與工具聲明**（呼應計畫書 §5.6）：

- ✅ **AI 產生初稿，研究者逐句複核與修改，並在論文如實揭露**（`ai_drafted: true`）
- ❌ **不可**把 AI 的標註當成「一位標註者」去算兩人 Kappa——那與計畫書 §5.6「核心工作由研究者主導」的聲明矛盾，是拿工具聲明換一個數字，不值得
- ✅ Kappa 另找**一位真人**獨立標註重疊的 30 句來算（可與 §7.5 的評測員之一重疊）

**自造的 40 句先造完封存**，不得邊看系統表現邊回頭調整句子——否則測試集被污染，等於變相在測試集上調參。

> ⚠️ **Open Q D（已定案）**：AI 初稿 + 研究者全數複核並揭露；Kappa 另找真人標重疊 30 句；自造 40 句先封存。

### 8.1 S0 spike 規格

**目的**：在蓋抽象層之前，確認主力模型撐不撐得住反思任務。理由不是「榜單中文分數低」（那測的是知識問答，不是歧義偵測），而是三項**與本系統機制直接對應**的能力：

| # | 測什麼 | 怎麼測 | 判準 |
| --- | --- | --- | --- |
| T1 | **Schema 通過率** | 同一錨點 schema 重複 k 次，統計走到降級階梯第幾級、各級成功率 | 對應 G6 ≥ 99% |
| T2 | **該標 UNKNOWN 時會不會亂猜** | 句子含「原文無從判定」的欄位，看模型填 UNKNOWN 還是編一個值 | 亂猜率愈低愈好 |
| T3 | **回譯相似度是否真的掉** | 高歧義句 vs 低歧義對照句，比較 en/ja 回譯的一致性分數 | 兩組要能分開，否則整個偵測機制的訊號不存在 |

**設計**：10 句高歧義 + 5 句低歧義對照（**對照組必要**——沒有它 T3 只會得到一個無從解讀的數字），跑校內全部可用 LLM。

**產出**：`data/spike/results.json` + 一張比較表。這份數據**直接併入 M8 的跨模型對比**，不是純丟棄——丟棄的只是腳本本身。

### 8.2 S0 執行結果（2026-08-09）

腳本 `scripts/spike_s0.py`，句集 `data/spike/sentences.json`（歧義 10 + 對照 5），每句重複 3 次，校內全部 6 個 LLM。

| 模型 | T1 通過率 | tier 分布 | T2 recall | T2 對照誤標 | T2 precision | T3 歧義 | T3 對照 |
| --- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| `mistral-small-4` | 100% | 全 tier2 | 40.0% | 40.0% | 28.6% | 0.843 | 0.961 |
| `gpt-oss-120b` | 100% | 全 tier1 | 40.0% | 40.0% | 28.6% | 0.823 | 0.983 |
| `llama4scout` | 100% | 全 tier1 | **10.0%** | 30.7% | **11.5%** | 0.884 | 0.968 |
| `nemotron-3-ultra` | **60%** | tier2/tier3 | **70.0%** | **62.9%** | 38.9% | 0.869 | 0.948 |
| `ornith-35b` | 95.6% | 全 tier2 | 31.0% | 31.4% | 29.0% | 0.884 | 0.953 |
| `diffusiongemma-26b` | 100% | 全 tier3 | 50.0% | 32.0% | 38.5% | 0.843 | 0.952 |

`recall` = 該欄位確實無從判定時標對 UNKNOWN 的比率；`對照誤標` = 對照句上誤標 UNKNOWN 的比率；`precision` = tp/(tp+fp)。

**發現 1：降級階梯設計成立（G6 達標）**
六個模型的 schema 通過率都是 100%，除了 `nemotron-3-ultra` 只有 60%。三種 tier 各有模型實際用到（tier1 兩個、tier2 三個、tier3 一個），證明階梯不是過度設計。`diffusiongemma-26b` 完全靠 tier3 寬鬆解析達到 100%——若當初假設 `json_schema` 可用，這個模型會直接不能用。

**發現 2：UNKNOWN 標記幾乎不承載資訊** ⭐

初版只量了 recall（該標時有沒有標），得到「欄位梯度」（social_relation 76.6% > agent 47.1% > speaker_intent 7.2%）並解讀為「模型願意承認不知道上下關係，卻總要斷言意圖」。**加入 precision 後這個解讀被推翻**——那個梯度只是各欄位的標記基準率，不含判別力：

| 欄位 | 該標時標對（recall） | 不該標卻標（FP） | 判別力 |
| --- | :-: | :-: | :-: |
| `agent` | 24/52 = 46.2% | 44/81 = 54.3% | **−8.2pp** |
| `social_relation` | 36/49 = 73.5% | 78/81 = 96.3% | **−22.8pp** ⚠ |
| `speaker_intent` | 5/68 = 7.4% | 13/81 = 16.0% | **−8.7pp** |
| `tense` | （無此類句） | 2/81 = 2.5% | — |
| `register` | （無此類句） | 14/81 = 17.3% | — |

**三個欄位的判別力全為負**。也就是說，模型標 UNKNOWN 的傾向與「該欄位是否真的無從判定」無關，甚至輕微反向。問題不是「模型不肯承認不確定」，而是**模型的不確定性標記根本不承載資訊**。

`nemotron-3-ultra` 是最好的例證：recall 最高（70.0%），但誤標率也最高（62.9%），precision 落回 38.9%。**它的「誠實」只是把 UNKNOWN 標得比較兇的副作用**，不是判別力。這也印證 §8.2 稍早提出的倖存者偏差疑慮。

> ⚠️ **本表的量測缺陷（須承認）**：對照句是按「語意不歧義」挑選的，**不等於「每個欄位都可判定」**。例如「他去年從台北搬到台中」根本沒有受話者，`social_relation` 本來就無從判定——所以該欄位 96.3% 的「誤標」很可能是**正確行為**，不是錯誤。
>
> 因此：**`agent` 的負判別力結論成立**（對照句如「我明天早上九點會在辦公室等你」的施事者明確為「我」，卻仍有 54.3% 被標 UNKNOWN）；**`social_relation` 的結論無效**，不可引用。
>
> **修正方式**：determinability 必須**逐欄位標註**，不能只在句子層級標一個 `text_determinable`。這直接影響 §7.6 的 CAD-100 schema，且必須在 A0 開工前修好。

**修法已在計畫書內**：§4.3 承諾的 `alternative_readings`（「生成多個可能的語意解釋並標示其適用情境」）正是解法。不要問「意圖是什麼（或 UNKNOWN）」這種單值自我評估題，改為**強制列舉所有與原文相容的讀法，再問原文本身能否決定**。因此該欄位由選配升為**必要**（影響 Open Q A）。

**發現 3：回譯一致性訊號存在但弱，兩組無法完全分離**
對照組平均一致性一律高於歧義組（落差 0.085–0.159），方向正確；但**六個模型全部 `separable = False`**，即歧義組最高分 > 對照組最低分，分布重疊 0.015–0.174。

意涵：演算法 1 的 `Score < τ` 判準必然有偽陽性與偽陰性，單一閾值切不乾淨。這強化了 §4.1 的設計（Router 不能只靠回譯一致性），也預告 M5 要正視偵測誤差。重疊最小的是 `mistral-small-4`（0.017）與 `nemotron-3-ultra`（0.015）。

**發現 4：`temperature=0` 不保證確定性輸出** ⚠️
同一設定跑兩次，`mistral-small-4` 的 T3 歧義組平均由 0.8235 變 0.8772，`diffusiongemma-26b` 的 T2 由 43.3% 變 50.0%。vLLM 的批次排程會引入非確定性。

意涵：§5.4 的**呼叫快取由「省錢措施」升級為「可重現性的必要條件」**；且本表所有數字都帶有未量測的執行間變異，正式評測必須多次執行取平均並報標準差。

**方法論警告**：T2 只在 schema 成功的樣本上計算，因此 T2 與 T1 條件相依。`nemotron-3-ultra` 的 76.5% 是在 **17 個樣本**上算的（其餘模型 30），且失敗樣本很可能集中於難句，**其「較誠實」的表象可能是倖存者偏差**。正式評測中 T2 必須改為在「所有模型都成功」的配對子集上計算。

**Open Q I 結論**：`reflect` 角色用 **`gpt-oss-120b`**——T2 與 mistral 並列最佳（40%），且是唯二支援 tier1 嚴格結構化輸出者，反思階段的輸出結構最複雜、最需要它。`mistral-small-4` 續留 translate / backtrans（快且 T1 穩）。`llama4scout` 不適任任何需要不確定性判斷的角色（T2 僅 13.3%）。

> ⚠️ **T2 的定位必須改變**：這個發現已有文獻先行（見 §8.4），**不能當本研究的貢獻，只能引用**。貢獻全部移到修法。

### 8.3 S0b — T3 訊號追查（2026-08-09）🔴 **全數作廢，見 §8.6**

> 保留本節僅為記錄推論過程，**任何數字不得引用**。詳見 §8.6。

S0 的 `separable = False` 一度被判讀為演算法 1 地基不穩。追查後結論是：**部分為統計量選擇錯誤，訊號本身堪用**。

腳本 `scripts/spike_s0b.py`。設計原則是**翻譯固定、只換量測工具**（同一批回譯套四種尺規），變因只剩尺規本身；另加一組決定 RQ2 存亡的對照。

| 量測方式 | AUC | 標準差 | 歧義組均值 | 對照組均值 |
| --- | :-: | :-: | :-: | :-: |
| V2 雙編碼器 vs 原文 | **0.840** | 0.000 | 0.832 | 0.939 |
| V1 雙編碼器互比（S0 所用） | 0.820 | 0.000 | 0.827 | 0.950 |
| V3 交叉編碼器 rerank | 0.800 | 0.000 | 0.805 | 0.972 |
| **S5 LLM 直接問「歧不歧義」** | **0.550** | 0.000 | 0.700 | 0.600 |
| **V4 LLM 判「兩回譯意圖是否相同」** | **0.500** | 0.000 | **1.000** | **1.000** |

**修正：`separable` 是錯誤的統計量** ⚠️
S0 用的「歧義組最高分 > 對照組最低分」criterion 過於嚴苛，n=15 下任何含雜訊的量測都會失敗，把訊號說得比實際差。正確統計量是 **AUC**，而 AUC 0.84 屬中等偏好的判別力。**演算法 1 的地基沒有崩塌**；真正的問題是單一固定 τ 必然誤判 → 改報 ROC 曲線並以 §4.1 多訊號補強（Open Q L 選 a+b），而非推翻設計。

**發現 5：機械量測遠勝 LLM 自我評估** ⭐⭐ — 本專案目前最重要的結果

- 機械量測（embedding / reranker）：AUC **0.80–0.84**
- LLM 自我評估（S5 直接問歧義、V4 判意圖異同）：AUC **0.50–0.55**

V4 尤其極端：模型對**每一組**回譯都回答「意圖完全相同」，歧義組與對照組一律 1.000，判別力為零。S5 也近乎亂猜（0.70 vs 0.60）。

這與 §8.2 發現 2 是**同一個病理的兩次獨立顯現**：要模型做自我評估（我確定嗎／這兩個一樣嗎／這句歧義嗎），它失效；換成機械量測（兩個譯本量起來差多少），訊號就出來。

> **這是多視角架構的真正立論**，而且比計畫書原本「多視角能消除單一視角盲點」的說法紮實得多：
>
> **多視角驗證的價值在於它把「模型做不到的自我評估」轉換成「模型不必參與的機械量測」。**
>
> 同一個洞察也解釋了 §8.2 的修法為何有效——承認 UNKNOWN 是自我評估（模型抗拒），列舉讀法是生成（模型樂意）。修法不是說服模型誠實，而是**改變輸出結構，讓誠實不需要自我否定**。

**RQ2 的立論基礎成立**：最佳多視角量測 0.840 vs 最佳直接詢問 0.550。既然直接問幾乎無訊號，慢速通道的成本有正當理由。⚠️ 但 n=10 vs 5 檢定力極低，**dev-30 完成後必須重跑才能寫進論文**。

**副產品：AUC 對非確定性免疫**
三次重複的 AUC 標準差全為 0.000——AUC 是秩統計量，對 §8.2 發現 4 的數值抖動不敏感。**評測主指標優先採用秩統計量**，可大幅降低非確定性帶來的重跑成本（減輕 Open Q K 的壓力）。

**未獲支持的假設**：交叉編碼器（0.800）並未勝過雙編碼器（0.820），儘管其組間落差更大（0.167 vs 0.123）。落差大不等於判別力高。改成「與原文比」則有小幅助益（0.820 → 0.840）。

**Open Q E 定案**：`bge-m3-embedding` + V2 比法（回譯與原文比，取兩者最小值）。

### 8.5 S0c — 跨語言 vs 同語言：§4.4 類型學主張的直接檢驗（2026-08-09）🔴

S0b 只證明「行為訊號優於自陳訊號」，未證明訊號來自計畫書 §4.4 主張的**日英語法強制顯性化**。本實驗做完全配對的對照：同溫度、同樣本數、同量測，唯一變因是第二個樣本換語言還是換一次取樣。

**先記一個實驗事故**：初版用「相同請求重送兩次、temperature=0.7」取同語言樣本，結果 **45/45 譯文完全相同**——端點會快取相同請求。實測 temperature 有被吃進去（不同溫度譯文確實不同），但相同 `(model, messages, temperature)` 重送必回快取，`temp=1.5` 重送四次仍只得 1 種。**同語言重取樣必須用單一請求的 `n=k` 參數**（`n=4` 實測得 3 種相異）。初版結果已作廢，保留於 `results_s0c_INVALID_cached.json`。

修正後結果（temp=0.7，`n=2`，3 次重複）：

| 條件 | V1 兩譯本互比 | V2 各自與原文比取最小 | 譯文全同 |
| --- | :-: | :-: | :-: |
| A 跨語言 en+ja | 0.823 | 0.820 | 0/45 |
| B 同語言 en+en | 0.770 | 0.840 | 15/45 |
| C 同語言 ja+ja | 0.817 | **1.000** | 6/45 |
| D 跨語言 en+de | **0.827** | 0.773 | 0/45 |

**發現 6：本樣本無法分辨跨語言與同語言，`ja+ja` 為待驗證假設**

- **V1（樣本間一致性）**：跨語言 0.823 / 0.827 vs 同語言 0.770 / 0.817。四個數字落在彼此的雜訊區間內（SE ≈ 0.11），**正確結論是「分不出」，不是「相當」**。
- **V2（與原文往返保真度）**：單一日文往返取 min 得 1.000。排列檢定 p ≈ 1/6435，Bonferroni × 8 後仍 < 0.0013，**統計上不能當雜訊打發**。

⚠️ **但這不足以動搖 §4.4，理由不在統計而在設計**：

1. **那 15 句已經是訓練集**。T2 欄位分析、T3 訊號選擇、V4 問法修正、本次語言比較——**同一批自選句子上迭代四輪**。統計修不了這件事，只有換資料能修。
2. **多重比較**：本表 4 條件 × 2 訊號 = 8 個 AUC，取最大值當結論。8 個含雜訊估計的最大值系統性偏高。且研究者自由度不只 8（哪個 embedding、min 還是 mean、哪種聚合都試過）。
3. **AUC = 1.000 的 CI [1.00, 1.00] 不可信**。Hanley–McNeil 在 A→1 時 SE→0，是已知假象；**拔靴法同樣退化**（完美分離的資料每次重抽仍完美分離）。應改用排列檢定取 p 值，並如實說明 CI 無有用形式。
4. 日文往返保真度最高（0.912）可能是 `mistral-small-4` 的模型特性而非語言特性。
5. V2 機制是「往返保真度取 min 兩次」，**不是樣本間一致性**，與三角測量不同機制，兩者不可混談。

**結論**：`ja+ja` 高分是**一個強假設，不是一個發現**。列入 dev-30 的預先登記清單，**不觸發任何重新設計**。

⚠️ 檢定力提醒：dev-30 對「V2 是否優於隨機」充裕（z ≈ 6.8）、對「V2 vs V4」勉強（z ≈ 3）、對「跨語言 vs 同語言」（0.82 vs 0.77）**完全不夠**。§4.4 要等 CAD-100，不要指望 dev-30 定案。

**發現 6b：§4.4 是兩個主張，只有一個被挑戰** ⭐

計畫書 §4.4 實際綁了兩個可分離的主張：

| | 主張 | 本次證據 | 狀態 |
| --- | --- | --- | --- |
| **(a)** | **類型學強制顯性化**：某些語言的語法強制標記出中文隱含的資訊 | 日文勝出**反而支持**——敬語正對應本批句子的語用／社會關係歧義 | 🟢 未受挑戰，且獲間接支持 |
| **(b)** | **三角測量**：必須多視角互比才能偵測 | 同語言重取樣未被分辨出較差；單探針 V2 表現亦佳 | 🟡 受挑戰，待 CAD-100 |

**分辨 (a) 是類型學還是「mistral 日文剛好好」的方法**——兩個檢定，都不需要新資料：

1. **分型檢定**：若為類型學效應，日文優勢應**集中在語用／社會關係類、在詞彙歧義上消失**；若為模型特性，則各類型均勻。dev-30 的 9/9/12 分層正是為此設計。
2. **跨模型檢定**：以校內 4 個模型重跑。若日文優勢跨模型穩定 → 類型學；若只在 mistral 上出現 → 模型特性。

**發現 7：自我評估的失效有一部分是問法造成的** ⭐

S0b 的 V4（問「兩句意圖是否相同」）AUC 0.500，模型對所有句子一律回答「相同」。改為**強制列舉差異**（「列出兩者在說話者意圖上的具體差異，若完全相同則輸出『無差異』」）後，AUC 回到 **0.660**，全零比例 27%，平均列舉 1.60 項。

所以 0.500 是**問法造成的退化輸出，不是能力不足**。這修正了 §8.3 發現 5 的部分表述：自我評估並非一律無效，**是／否的自我評估題會退化，強制生成題則保有部分訊號**。這與 §8.2 的 UNKNOWN → `alternative_readings` 修法是同一個機制，兩處互相印證。

但 0.660 仍低於機械量測的 0.82–0.84，且 CI [0.37, 0.95] 極寬。

**發現 8：德法皆堪用為留出語言**

往返保真度：ja 0.912 > fr 0.909 > en 0.897 > de 0.878（最低值 de 0.636 / fr 0.647）。**四者同級，德法均無品質疑慮**，Open Q F 的前置條件滿足。

### 8.6 長度混淆 — T3 全家作廢（2026-08-14）🔴

在 dev-30 上跑長度基準分類器時發現嚴重問題，回頭套用到 spike 的 15 句後確認：**§8.3 與 §8.5 的所有 AUC 數字均不可報告。**

**spike 15 句的長度分布**：

| 組別 | n | 平均字數 | 範圍 | 特徵 |
| --- | :-: | :-: | :-: | --- |
| 歧義組 | 10 | 7.7 | 5–16 | 多為短口語 |
| 對照組 | 5 | 11.8 | 10–14 | 全為完整敘述句 |

**只用句長的分類器 AUC = 0.900**（SE ≈ 0.082）——**高於 V2 的 0.840**。一個只數字數的分類器打敗整條多視角管線。

**直接證據**——一致性分數與句長的皮爾森相關：

| 量測 | r(長度, 分數) |
| --- | :-: |
| V1 雙編碼器互比 | +0.426 |
| V2 與原文比 | **+0.469** |
| V3 交叉編碼器 | +0.265 |
| **S5 LLM 直接詢問** | **+0.057** |

機械量測強烈依賴長度，S5 幾乎不依賴。**因此「機械量測 0.84 勝過自評 0.55」這個頭條，差距完全可能是長度造成的**——兩者對長度的敏感度根本不同。

**作廢範圍**：

- ❌ §8.3 全部（V1/V2/V3/V4 的 AUC、DeLong 檢定）
- ❌ §8.5 全部（四條件八個 AUC、`ja+ja` = 1.000、發現 6 與 6b 的證據基礎）
- ⚠️ §8.2 的 T2 **同樣受污染**（見下），T1 schema 通過率不受影響
- ✅ §8.5 發現 7（V4 改良問法 0.500 → 0.660）的**方向**仍成立，但數值不可引用
- ✅ §8.5 發現 8（德法往返品質）不受影響（組內量測，非組間比較）

**根因**：spike 的歧義組與對照組是**各自獨立挑選**的，長度零約束。歧義多來自省略，省略就是短；對照要求語意明確，明確就要把資訊寫出來，寫出來就長。**這是任務本身的結構性偏差，不是選句失誤。**

**T2 亦受污染，但偏誤方向對結論不利**（`r(句長, UNKNOWN 標記數)`）：

| 模型 | 歧義組內 | 對照組內 |
| --- | :-: | :-: |
| `mistral-small-4` | −0.429 | **−0.861** |
| `gpt-oss-120b` | −0.312 | **−0.861** |
| `llama4scout` | −0.249 | −0.642 |
| `nemotron-3-ultra` | −0.109 | −0.525 |
| `diffusiongemma-26b` | −0.231 | −0.389 |
| `ornith-35b` | +0.330 | −0.142 |

組內 |r| 中位數 0.359、最大 0.861。⚠️ **跨模型合計會相消**（ornith 為正、其餘為負，合計僅 −0.117），不可用合計值判斷。

偏誤方向推算：歧義句短（7.7）、對照句長（11.8），多數模型「愈長 → 標愈少 UNKNOWN」⇒ 歧義組 recall 被膨脹、對照組 FP 被壓低 ⇒ **兩者都讓判別力看起來更好**。在偏誤已使其高估的前提下實測仍為負，因此「UNKNOWN 不承載資訊」是**保守估計**，方向性結論保留；但**數值同 T3 不可報告**，須在 dev-30 上重測。

**處置**：spike 那 15 句退役，未來所有訊號量測改在 dev-30 的最小對立對上跑（長度 AUC 已修正至 0.520）。

> 💡 **這件事本身值得寫進論文的方法章**：「歧義句 vs 非歧義句」在資料集構造上天然帶長度偏差，**任何不做長度基準的歧義偵測評測，都可能在報告一個長度分類器的成績**。這比 spike 那些作廢的數字有價值得多。

| `V1+V2+NP` | 155／132 | 0.639 | [0.575, 0.702] | 0.139 | 對照較長 |
| … | | | | | |
| `全部+VP+的+NP` | 307／130 | 0.279 | [0.224, 0.334] | 0.221 | 歧義較長 |
| `ADJ+N1+N2` | 72／50 | **0.229** | [0.141, 0.317] | 0.271 | 歧義較長 |

**18 組中 12 組的 CI 排除 0.5：7 組對照較長、5 組歧義較長。**

⚠️ **中位數 0.490 不是「乾淨」，是正負相消。** 兩端各有效應量 0.23 與 0.27 的顯著組別。而 18 種結構正是 CHA-Gen 的設計核心，**分結構分析是最自然的用法**——那時混淆就是活的。

**方法學結論改寫**（取代原本的「普遍存在長度混淆」）：

> 不是「資料集普遍有長度混淆」（n=2 撐不起對領域的主張），
> 而是「**聚合層級的長度稽核會掩蓋結構層級的混淆**」。
>
> - **Wu et al.** = 聚合層級就爆掉的極端案例（0.965）
> - **CHA-Gen** = 聚合層級近乎乾淨（0.418，效應 0.082）、**結構層級有異質性**（12/18 顯著，雙向）
>
> 兩者都指向同一條操作建議：**稽核必須分層做**。只報聚合數字會漏掉一半的問題。

**對本專案的直接影響**：`length_audit` 必須逐子類別報告 CI 與方向，不能只報整體（v3 架構書 §P2 已列此檢查項，本結果是它的實證理由）。

⚠️ 另記：CHA-Gen 的 `sentence_pair.csv` **不是最小對立對**。例「伤害的是敌人。」配的是「被责备的是他。」——同結構的另一句，不是同句的消歧版。這解釋了它為何沒有長度偏差，也說明它與本專案的 minimal pair 不是同一種設計。

#### 8.6.3 CHA-Gen 的兩項發現與本專案的已知限制

| CHA-Gen 的發現 | 對本專案的影響 |
| --- | --- |
| **指令微調誘發過度自信，Base 模型較能捕捉語意多樣性** | 本專案全部使用 instruct 模型（校內 API 只提供 instruct）。**這是已知限制，宣告即可，不補跑 base**——補跑需要另一套基礎設施，且該論文已做過 |
| **模型偏好主流（dominant）解讀** | 直接影響 probe 篩選：若 gold 就是最高頻義項，模型答對可能是猜對而非理解脈絡。故 §2-3 的判準改為**優先選 gold ≠ 最高頻義項**的題目 |

> ⭐ 修正後仍可獨立成立的成果：Wu et al. 2025 的成對消歧句可被「只數字數」的分類器以 AUC 0.965（n=136、SE 0.012、CI [0.94, 0.99]）分開。該資料集是為「生成消歧版本」設計的，非為偵測而設計——**有問題的是把它當偵測負例，那是本專案的用法不是原作者的主張**。此發現不依賴本專案系統是否有效。但它是**單一資料集的案例**，不足以支持對領域的普遍主張。

#### 8.6.4 ⭐ 主結果換位（2026-08-18 裁示）

| | 舊規劃 | 新規劃 |
| --- | --- | --- |
| **主結果** | 評測方法學（長度混淆） | **U/A/B 脈絡敏感度實驗** |
| 方法學 | 主結果 | **降為 methods 章節的一節** |

**三個理由**：

1. **方法學 n=2 撐不起主結果。** 兩個資料集（其中一個還是聚合層級微弱）無法支持對領域的普遍主張。
2. **U/A/B 保證有結果。** `insensitive`（條件 A 與 B 選到同一義項）是**純客觀**的——它不需要知道哪個義項才對，只需要知道兩個脈絡的答案應該不同。不依賴任何歧義標註，**數字高低都可報告**。
3. **CHA-Gen 乾淨讓定位更清楚。** 我們不是修正他們，是問不同的問題：
   - **句子層級的歧義偵測**（CHA-Gen 測的）：這句話有沒有多種讀法
   - **脈絡敏感的義項選擇**（本專案測的）：給定脈絡，模型能否選對它許可的義項
   - 這是**兩種能力**，現有基準測的是前者

#### 8.6.6 🔴 U/A/B 脈絡恆等設計不適用於 WSD 資料源（2026-08-18）

> **這個否定結果本身可寫進報告的方法章。** 它說明了一類資料源與一類實驗設計
> 在需求上為何相反，而那不是實作問題，是概念問題。

**發現經過**：以 CWN-SemCor 建 U/A/B 三元組後粗跑 10 筆，測得 U 與 A 選到
同一義項的比例為 **7/8（88%）**。初判為「脈絡沒做工」，實查後發現更根本的原因。

**根因**：CWN-SemCor 是**詞義消歧（WSD）的 gold standard**——六位語言學背景
標註者看句子標出正確義項。要標得出來，**義項就必須可由該句決定**。

實測 60 筆候選中 **59 筆（98%）**的句子只有一個子句，決定義項的線索全在目標詞
所在的子句內。因此：

| 條件 | 預期角色 | 實際 |
| --- | --- | --- |
| U（子句單獨） | 無脈絡、義項未定 | **已經決定了** |
| A（加脈絡） | 脈絡鎖定義項 A | 加了也沒差（脈絡去標點後只剩 0–5 字元） |
| B（另一脈絡） | 脈絡鎖定義項 B | 不是鎖定，是**推翻**標註者的判斷 |

**U/A/B 需要「無脈絡時未定」的題目；WSD 資料集提供「有脈絡時已定」的題目。
這是相反的需求，調整篩選條件無法解決。**

88% 這個數字可能就是正確答案：那些題目本來就不歧義。

**處置**：

1. 主線改為 **MT 詞義錯誤基準**（DiBiMT／MuCoW 一系）：
   CWN-SemCor 句子 → 翻成英文 → judge 判譯文表達哪個義項 → 比對 CWN gold。
   不需要 U/A/B、不需要 C_B、不需要人工快篩。
2. **U/A/B 未廢棄，降為次要實驗**，僅適用於**語用歧義**——
   「方便的話明天再說吧」不加脈絡確實是未定的，那是真的脈絡依賴。
   資料來源為 dev-30 的 12 句語用題，脈絡框架由研究者撰寫。
   **主線出數字後再做。**
3. 同時移除的設計元素（因不再適用）：`probe_span`、`attested_condition`、
   對調平衡、脈絡長度配平、最小子句切分。相關的不變量測試已刪除而非註解。

⚠️ 連帶修正一個實作 bug：U/A/B 的翻譯提示採
`【Context】…【Target sentence】…` 結構，實測 **81% 的譯文仍是中文**（未翻譯），
且有內容竄改。改為單純的「翻譯這個句子」後 8/8 正常。
成因是該提示結構讓模型誤判任務，非模型能力問題。
新流程加入自動檢查：譯文 CJK 比例 > 30% 即標為 `translation_failed`，
不送進 judge，並單獨計數——**那是要報告的數字，不是要藏的錯誤**。

#### 8.6.5 ⭐ 預先登記的假設：gold 頻率分層（2026-08-18）

> 這條原本規劃為 P6 的事後分析，**已提升為資料層就支援的預先登記假設**。
> 理由：事後分析無法回應「題目是不是被挑成對模型難的」這個質疑，
> 分層抽樣可以。

**資料層設計**：`data/probes/` 依 gold 在同 lemma 中的語料庫頻率排名分層抽樣。

| 層 | 定義 | 配額 | 角色 |
| --- | --- | :-: | --- |
| `dominant` | gold **是**該 lemma 的最高頻義項 | 20 | **基準線** |
| `non_dominant` | gold **不是**最高頻義項 | 40 | 主測試 |

**為何不能全選非主流**：若 60 題全是 `non_dominant`，正確率 40% 無從分辨是
「模型不理解脈絡」還是「題目全設計成答案剛好不是模型的預設偏好」。
CHA-Gen 已發表「模型偏好主流解讀」，缺了主流層就無法回應這個質疑。

**主指標改為兩層之差**，而非單一正確率：

| 觀察 | 判讀 |
| --- | --- |
| 主流高、非主流低 | 走頻率捷徑，**沒有讀脈絡**（依 CHA-Gen 的預期） |
| 兩層相近 | **真的在讀脈絡** |
| 兩層都低 | 任務太難，或 `sense_judge` 有問題 |

這同時是**與 CHA-Gen 的可驗證銜接**：他們在句子層級發現模型偏好主流解讀，
本專案在脈絡層級檢驗該偏好是否導致脈絡失敏。若兩層差距顯著，兩者銜接而非競爭；
若不顯著，那本身也是可報告的差異。

**次要檢驗**（P6）：對每個 `insensitive` 案例（A 與 B 選到同一義項），
檢查模型選中的是否為該詞的最高頻義項，與隨機基準比較。

**對調平衡的實作**（同屬預先登記）：語料庫原句在**分層內交替**指派為條件 A 或 B，
保證每層各半。實測 60 筆得 `dominant` A=10／B=10、`non_dominant` A=20／B=20。
⚠️ 初版用 id 雜湊指派，實測得 A=23／B=37——**雜湊只是隨機，不是平衡**，
對調平衡的目的是均分自然度優勢，隨機無法保證。

### 8.7 雜訊基準 — PPL 與表層特徵（2026-08-14）

**dev-30 表層特徵基準**（消歧句為正例，n=30 對）：

| 特徵 | 全體 AUC | SE | 95% CI |
| --- | :-: | :-: | :-: |
| 字元長度 | 0.520 | 0.075 | [0.37, 0.67] |
| 標點總數 | 0.517 | 0.075 | [0.37, 0.66] |
| 是否含逗號 | 0.517 | 0.075 | [0.37, 0.66] |
| 相異字元數 | 0.513 | 0.075 | [0.37, 0.66] |
| 字元重複率 | 0.517 | 0.075 | [0.37, 0.66] |

全部落在雜訊內，**dev-30 表層乾淨**。

⚠️ 但分型檢視發現一項需記錄的結構性殘留：**`字元重複率` 在指代類 = 0.944**，比長度的 0.636 更強。成因明確——指代消歧把重複的「他…他」換成不同專名，重複率必然下降。n=9、SE ≈ 0.15 撐不起定論，但方向明確，**是比長度更難察覺的混淆**。處理方式同長度：留下並量化（報告時做殘差化），不硬修到 0.5，否則會扭曲句子自然度。

（分型欄一律只報「有無明顯異常」。n=9–12、SE ≈ 0.13–0.15，三個數字彼此與 0.5 皆無法區分。）

**原文 PPL 基準** — 這是可能讓多視角在偵測階段失去存在理由的實驗：

`ckiplab/gpt2-base-chinese`（102M，繁中），單次前向、不翻譯、不回譯，n=30 對：

| 方向 | AUC |
| --- | :-: |
| 假設「歧義 = 高 PPL」 | 0.484 |
| 假設「歧義 = 低 PPL」（間接套語頻率高） | **0.516** |
| 取較佳方向 | 0.516　SE ≈ 0.075　CI [0.37, 0.66] |

**PPL 訊號弱，架構的存在理由未受挑戰。** `r(句長, PPL) = -0.251`，PPL 不是長度的代理。

反面意涵：計畫書 §4.2 的 PPL 構想（已由 D4 降級為事後指標）現在連**單語原文版本**也證實無效，PPL 家族整體看衰，不宜納入 §4.1 成為第六個訊號。

⚠️ 保留：模型僅 102M，敏感度可能不足；但 0.516 正中 0.5，換大模型翻轉至 0.75 的機率低。

⚠️ **表述修正**：CI [0.37, 0.66] 完整涵蓋「0.6–0.75 = 有效訊號」這一整段，因此正確說法是**「沒有證據顯示 PPL 有用」**，不是「PPL 已證實無效」。實務決定（暫不納入 §4.1）不變，但論文不得寫成已證偽，須於 CAD-100（SE ≈ 0.04）重測。

**PPL 的局部變體**（`scripts/ppl_variants.py`）——整句 PPL 是全 token 平均，而歧義通常是局部的（「方便的話明天再說吧」的歧義只在「方便」兩字，在 9 個 token 上平均會被稀釋四五倍），故整句層級可能是**問錯了問題**：

| 變體 | 需標註 | AUC | 95% CI |
| --- | :-: | :-: | :-: |
| 整句平均 surprisal | 否 | 0.509 | [0.36, 0.66] |
| 句內最大 token surprisal | 否 | 0.610 | [0.47, 0.75] |
| **span 對 span surprisal** | 是 | **0.679** | [0.50, 0.86] |

**局部化梯度存在且方向符合預期**：0.509 → 0.610 → 0.679，愈局部訊號愈強。

**方向為「歧義處 surprisal 較低」**（歧義處 4.158 vs 替換處 5.122），與「間接表達是高頻套語」的假設一致。最穩固的一項是**句內比值 = 0.591**——歧義處的 surprisal 只有同句平均的 59%。這是**句內對照，長度效應自然抵銷**，不受 §8.6 的混淆影響，是本輪唯一免疫於長度問題的量測。

⚠️ 但三個 CI 皆涵蓋或貼近 0.5，**n=30 無法定案**，須於 CAD-100 重測。三種可能結局及其意義已寫入腳本說明：都 ≈0.5 → PPL 家族可寫死；span 高而 max 低 → 訊號存在但無標註定位不到（此落差本身可寫）；都高 → 便宜偵測器成立，RQ2 需重新定位。目前落在第二種的弱版本。

> 🔴 **本節初版的 span AUC = 0.851 為錯誤結果，已作廢**。當時拿「歧義句的 span surprisal」比「消歧句的**整句**平均」，是子片段對整句平均——常見套語對全句必然偏低，與歧義無關。改為 span 對 span 後降至 0.679。

**可行性記錄**：校內 API **拿不到原文 PPL**——`/v1/completions` + `echo=true` + `logprobs` 回 HTTP 500（LiteLLM proxy 不支援 legacy endpoint），chat 端的 `logprobs` 只有生成 token 而非 prompt token。故改用本地模型（原文 PPL 不必與主實驗同模型）。`torch 2.13.0+cpu` 有 Python 3.14 wheel，本地路線可行。
