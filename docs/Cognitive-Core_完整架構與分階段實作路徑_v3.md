## 1. 最終架構（定案，不再變動）

### 1.1 三個 RQ 的操作型定義

計畫書的三問不動，但操作化方式改了。改動理由與差異登記見 §7。

| RQ | 計畫書原文 | 本專案的操作型定義 |
| --- | --- | --- |
| **RQ1** | 模型如何知道自己「沒聽懂」？ | 能否**預測模型在翻譯時會選錯詞義** |
| **RQ2** | Router 如何讓簡單問題走快速通道？ | 成本–準確度前緣曲線上，E1 是否位於 B2 曲線上方 |
| **RQ3** | RAG + 滑動視窗如何避免 Lost in the Middle？ | 有無記憶模組的中段召回率對照 |

**RQ1 為何要改**：二元歧義標籤是主觀的，連 CHAmbi、Wu et al. 的作者都聲明其標註目標是與人類判斷對齊而非定義唯一正解。「模型有沒有選錯詞義」是客觀的，且直接就是下游損害本身，不是代理指標。

### 1.2 資料設計：脈絡恆等三元組 ⭐ 核心

> **所有實驗條件下，被測子句的字元序列完全相同；只變動被測子句以外的脈絡。**

```
條件 U：                    被測子句 S        ← 效度檢查
條件 A：脈絡 C_A          + 被測子句 S        ← 測試條件
條件 B：脈絡 C_B          + 被測子句 S        ← 測試條件
```

`S` 在三條件下逐字元相同。任何 U/A/B 之間的訊號差異，都不可能來自 `S` 的表面特徵。

**這一條結構性地消滅長度混淆**，不是量測後揭露，是讓它不可能發生。

#### 三個條件各自的角色

| 條件 | 角色 | 判準 |
| --- | --- | --- |
| U | **效度檢查**：確認這題真的需要脈絡 | 若模型在 U 也答對，脈絡沒做工，該題無效 |
| A | 測試 | 譯文應表達 `gold_sense_A` |
| B | 測試 | 譯文應表達 `gold_sense_B` |

#### 錯誤分類（客觀，零歧義標註）

| 錯誤型 | 定義 | 意義 |
| --- | --- | --- |
| `insensitive` | A 與 B 選到同一義項 | **模型忽略脈絡**，最強的錯誤訊號 |
| `wrong_A` / `wrong_B` | 選到該脈絡不允許的義項 | 選錯 |
| `correct` | 兩者皆符合 gold | 正確 |

`insensitive` 這一類尤其有力：**它不需要知道哪個義項才對，只需要知道兩個脈絡的答案應該不同。**

#### 兩條實作約束（違反就前功盡棄）

1. **U 條件必須是最小完整子句，不是字元視窗截斷。** 「目標詞前後 8 字」產出的是殘缺片段；模型翻譯片段的行為本來就與翻譯句子不同，那是用「片段 vs 句子」取代「短 vs 長」，換一個混淆而已。
2. **訊號必須量在被測子句的譯文上，不是整個輸入的譯文上。** 否則 A/B 多了前文，長度混淆又回來。`probe_span` 的字元起訖位置必須明確記錄並貫穿全流程。

### 1.3 資料來源

| 類型 | 來源 | 標註者 | 規模 |
| --- | --- | --- | --- |
| **LEXICAL**（主） | CWN-SemCor（HF `lopentu/Chinese-Wordnet-SemCor`） | 六位語言學背景母語者 | 28,836 原始句可篩 |
| **PRAGMATIC** | dev-30 的 12 句改寫為脈絡框架 | 研究者 | 12 |
| **REFERENTIAL** | dev-30 的 5 句 keep 項 | 研究者 | 5（**預測會失敗的對照組**） |

**CWN-SemCor 為何決定性**：義項來自 CWN 2.0 詞典編纂，句子來自中央研究院平衡語料庫，六位語言學背景母語者標註。相對地，dev-30 是單人 + LLM 起草，第一輪複核就有 13% 被標為「其實不歧義」。

**REFERENTIAL 為何降級**：日語同為 pro-drop 語言，對零主詞的強制顯性化能力比英語更弱，錨點語言逼不出來。這不是退讓——它是計畫書 §4.4 的**可檢驗版本**：

> 英語強制主詞／單複數／時態 → 對指代與時間歧義有效
> 日語強制敬語／社會關係　　 → 對語用歧義有效
> 兩者對詞彙歧義皆有效

若結果為真，這是論文的一張主圖。

                             ▼

      └──────┬──────┘    │   偵測：單探針往返保真度    │  ＝演算法 1
             │           │   診斷：多視角 IdentifyDiff│
             │           │            │              │
             │           │            ▼              │

             │           │            └─迴圈 ≤ R      │
             │           └────────────┬──────────────┘
             └───────────┬────────────┘
                         ▼
              ┌──────────────────────────────┐
              │ ④ Dynamic Memory              │  模組三
              └──────────┬───────────────────┘

              譯文 ＋ 決策摘要 ＋ 不確定性報告

**偵測／診斷分離**（§4.2.1）：原設計把最貴的操作（多視角平行翻譯）放在偵測階段，等於每句都付診斷成本。改為單探針往返保真度做偵測（一次翻譯 + 一次回譯），多視角只在慢速通道做診斷——因為單探針給不出「差異在哪」，而反思需要的正是那個。

# P2　資料層

## 需求

產出脈絡恆等的 U/A/B 三元組，主資料來自 CWN-SemCor。**這是全案最重要的一步**——資料設計錯了後面全錯。

## 技術細節

### 資料流

```
CWN-SemCor（展平）
  → groupby(test_sentence, test_word, test_pos) 還原
  → 取 label==True 的列得 gold sense
  → CwnGraph 查該詞的完整義項清單
  → 篩選：義項數≥2、目標詞出現恰一次、排除功能詞(P/Nes/DE)
  → 切出目標詞所在的最小完整子句 = probe_span
  → U = probe_span 單獨；A = 原句其餘部分 + probe_span
  → 人工快篩：U 條件下競爭義項真的都可能嗎
```

### 輸出 schema

```yaml
- id: lex-死-a3f2
  ambiguity_type: LEXICAL
  target_word: 死
  target_pos: VH
  probe_span: "還不如死了算了"          # U/A/B 下逐字元相同
  probe_span_offset: [12, 19]           # 在完整輸入中的字元起訖
  conditions:
    U:
      context: ""
      full_input: "還不如死了算了"
      gold_sense: null                   # 無脈絡，不可判定
    A:
      context: "他生了重病，痛苦得受不了，"
      full_input: "他生了重病，痛苦得受不了，還不如死了算了"
      gold_sense: "05035202"
      gold_definition: "形容生物失去生命。"
    B:
      context: "這場比賽輸得這麼難看，"
      full_input: "這場比賽輸得這麼難看，還不如死了算了"
      gold_sense: "05035211"
      gold_definition: "形容在競爭中被淘汰。"
  competing_senses:
    - {id: "05035202", definition: "形容生物失去生命。"}
    - {id: "05035211", definition: "形容在競爭中被淘汰。"}
  context_length_delta: 3                # |len(C_A) - len(C_B)|，須 ≤ 10%
  source: CWN-SemCor
  screened_by: researcher
  screened_at: 2026-08-xx
```

### length_audit 的檢查項

- 整體長度 AUC
- **各子類別內的長度 AUC**（整體 0.520 可能掩蓋子類別內的 1.000）
- 長度差的**方向性符號檢定**（不是絕對值，是符號是否系統性偏一邊）
- 字元數／詞數／標點數三種長度定義各算一次
- **`probe_span` 的長度 AUC 必須是 0.500**——脈絡恆等設計理論上保證這一點，跑出來證明它是 0.500，那個數字本身就是設計有效的證據

## 4. 全域規則（每階段開始前重讀）

### 地雷 1：長度與表層混淆 🔴

- **任何**組間比較先跑長度基準
- 脈絡恆等設計讓 `probe_span` 長度 AUC 必然是 0.500 —— 每次都跑一次證明它是
- 訊號 AUC 與**最強的雜訊 AUC 並列**呈現
- 表層特徵無限，**不要逐個修到 0.5**，量化揭露即可

### 地雷 2：循環論證

- 反思迴圈的終止條件就是「一致性 ≥ τ」，拿一致性比 E1 vs B0 是套套邏輯
- 一致性只作收斂診斷
- 留出語言（de）全程不進迴圈

### 地雷 3：標註污染

- 某題的標註在任何模型看過它之前凍結
- 模型輸出只能影響**準則完備性**，不能影響**個別題目的答案**
- 候選集只呈現不判斷，篩選是研究者的工作

### 地雷 4：不對稱的證據標準

- 對有利結果嚴格，對不利結果**同樣**嚴格
- 記錄總共試了幾個配置（研究者自由度）

### 地雷 6：並列造成的 AUC 上限 🔴（2026-08-21 新增）

AUC 只看排序，**分數相同的兩題只能貢獻 0.5**。訊號若把大量題目給成同一個
值，就有一個與判別力無關的硬上限：

```
AUC 上限 = 1 − 0.5 × P(隨機兩題同值)
```

實測：S4 成語在 400 筆中只有 8 筆非零，上限 **0.520**，
低於標籤完全乾淨時所需的 0.557——**它不可能顯著，與訊號好壞無關**。

**預先登記規則（實作於 `eval/gate.py`）**

```
所有訊號在計算 AUC 之前，先算並列上限。
上限 < required_auc 者，二選一：
  (a) 重新設計為連續分數        action=continuous
  (b) 標記為覆蓋率不足無法檢定  action=untestable
決定必須在看到任何 AUC 之前做完並記錄。
```

登記檔 `data/results/signal_preregistration.md` 附時間戳與 commit hash，
且自證 `labels_used: false`（並列上限只依賴訊號值的分布）。
AUC 閘門拒絕未登記的訊號。兩者合起來就是「訊號設計未受結果影響」的證據。

⚠️ 「上限低於門檻」與「訊號無預測力」在報告中**必須明確區分**。
