# prompt 洩題事件記錄

> 本檔記錄本專案三次 prompt 污染事件的完整細節，供報告方法章引用。
> 守門測試：`tests/test_prompt_contamination.py`

---

## 為什麼要記這個

三次事件都是**同一個模式**，而且都不是疏忽或趕工：

> 撰寫 prompt 需要 few-shot 範例；最順手、也最貼切的範例，
> 就是撰寫者剛剛處理過的真實資料。

在傳統的研究分工中，寫 prompt 的人與準備資料的人往往是同一人，
但 prompt 通常只是「介面」而不是「會看到答案的東西」，所以沒有人把它
納入污染檢查的範圍。**LLM 輔助研究把這件事放大了**：助理同時經手資料
清洗、結果分析與 prompt 撰寫，它從自己剛剛看過的樣本裡取例子是最自然的行為。

污染的後果有一個惡劣的性質：**從結果完全看不出來**。
被洩題的題目照樣產生分數、照樣進入統計，只是那些分數不再有意義。
沒有守門測試就沒有任何訊號會提示這件事發生過。

### 事件 1　`prompts/router.md` v2

| | |
| --- | --- |

### 事件 3　`prompts/sense_judge.md` v3（二元版）

| | |
| --- | --- |
| 發現方式 | 守門測試**補強之後**才抓到——第一版看不見 |
| 載體 | **英文譯文** 與 **CWN 義項定義** |
| 內容 | `Occasionally, a few kind people bring me something to eat.`、`Every street in Forest Home`、`用手取物或持物。`、`形容生物失去生命。` 等 |
| 為何是洩題 | 譯文取自探針 `wsd-拿-7496`、`wsd-條-63fe`；定義是 `拿`／`死` 的競爭義項 |
| 影響 | **9/400 題（2.2%）**。其中 judge 判對 4、判錯 4、NONE 1——**無系統性灌水** |

⚠️ 事件 3 揭示了守門測試的一個缺口：第一版只掃 prompt 正文中**被引號或
反引號包住的中文片段**，因此看不到（a）英文譯文，（b）以純文字形式寫成
`A：用手取物或持物。` 的義項定義。**偵測器本身也需要被檢驗涵蓋範圍。**

## 緩解方式

`tests/test_prompt_contamination.py` 對**四種載體**做程式化掃描：

| 載體 | 比對方式 | 資料來源 |
| --- | --- | --- |
| 評測原句 | prompt 中的引號片段 ⊂ 探針句 | `wsd_probes.yaml` |
| 英文譯文 | 探針譯文 ⊂ prompt 正文 | `wsd_baseline400.json` |
| 義項定義 | CWN 定義 ⊂ prompt 正文 | `wsd_probes.yaml` 的 `competing_senses` |
| 既有資料集 | prompt 中的引號片段 ⊂ dev-30 文本 | `dev30/sentences.yaml` |

三個設計要點：

1. **只掃 `render()` 會送出的部分。** frontmatter 的 changelog 必須能寫出
   「被換掉的是哪一句」，把它算成違規會讓測試永遠失敗，於是被繞過——
   那比不做檢查更危險。
2. **偵測器自己要有反向測試。** 三支 `test_detector_catches_*` 人工造出
   違規樣本，確認偵測器抓得到。否則它可能只是一個永遠通過的裝飾。
3. **產出盲標表前也要跑同一套檢查。** `make_judge_manual.py` 會排除
   出現在任何 prompt few-shot 中的題目——驗證集若被洩題，
   算出來的一致率會系統性偏高。

## 報告方法章用的段落

> **AI 協作研究引入了一種新的污染管道。** 撰寫 prompt 的助理會從它處理過的
> 資料中選取 few-shot 範例——這是最自然也最貼切的取材方式，卻等同於把評測
> 題目的答案寫進系統提示。本專案三次遭遇此問題（`router.md`、`reflect.md`、
> `sense_judge.md`），涉及四種不同的載體：評測原句、模型譯文、詞義定義，
> 以及既有資料集的標準答案。三次皆由守門測試在事後偵測——其中第三次是在
> **偵測器本身被補強之後**才浮現，顯示偵測範圍需要與 prompt 的內容形態同步演進。
>
> 此類污染的關鍵性質是**從結果不可見**：受影響的題目照常產生分數並進入統計。
> 本專案受影響的比例為 9/400（2.2%），其中判對 4 題、判錯 4 題，未造成
> 系統性偏移；但這是事後查核的結果，不是設計保證。
>
> 緩解方式為對四種載體進行程式化掃描，且偵測器自身附反向測試以確認其涵蓋
> 範圍。在 LLM 輔助研究日益普及的情況下，我們認為 prompt 應被視為
> **可能洩題的實驗材料**，納入與訓練／測試切分同等的污染管控。
