## 2　v1 的 10 筆不一致拆成四類

不是同一種錯，混在一起看不出該修什麼。

| 類型 | n | 內容 |
| --- | :-: | --- |
| **A　無詞彙對應即判 NONE** | 2 | 03 強、18 去 |
| **B　對英文單字做義項匹配** | 3 | 04 收、16 拿、17 深 |
| C　人工與 gold 不同（judge 同 gold） | 3 | 08 掛、10 去、12 條 |
| D　三方都不同 | 2 | 19 當、20 條 |

**只有 A+B 共 5 筆是 judge 明確錯**（人工與 gold 一致、judge 不同）。
C 那 3 筆 judge 其實與 gold 相同。

### A　把「找不到對應的英文詞」當成「語義沒被傳達」

| 原句 | 譯文 | judge |
| --- | --- | --- |
| 四**強**交叉準決賽 | semi**finals** crossover | NONE「譯文未出現與『強』相關的意涵」 |
| 親手**去**使用這些資料 | personally use this data | NONE「譯文未出現與『去』相關的動作或方向義」 |
| 每**條**街道 | Every street | NONE「譯文未出現與『條』相關的量詞或概念」 |

三筆的語義都有傳達，只是由英文的詞形（semifinals）、語序、或
「Every ＋可數複數」的句構承擔，不是由單一個詞承擔。

v1 prompt 的例三只教了「沒譯出 → NONE」，judge 遂把兩者等同。

### B　挑一個英文單字，判斷那個英文單字的意思

| 原句 | 譯文 | judge 的依據 | 正解 |
| --- | --- | --- | --- |
| 我們不**收**支票 | do not accept checks | 「accept checks 為接到支票」→ 接到 | 收取金錢 |
| **拿**東西給我吃 | bring me something to eat | 「bring 表用手取物或持物」→ 用手取物 | 提供…給後述對象 |
| 自己**深**知道 | know full well | 「full well 中的 well 表程度高且負面」 | 超過平常的程度 |

第三筆的依據是明顯的胡扯——`well` 不帶負面。但信心給了 0.85。

v1 prompt 的例二（「`bank` 為商業機構」）示範的正是這個作法。

## 4　真正的瓶頸不是 judge，是義項粒度

v2 剩下的 8 筆不一致中，多數是**英文譯文根本無法區分的義項對**：

| 詞 | 譯文 | 兩個候選義項 |
| :-: | --- | --- |
| 低 | the lowest record | 數值**小於比較對象**　vs　數值**變小** |
| 去 | most frequently visited | 向特定地點**移動**　vs　隨動作**到達**前述地點 |
| 去 | personally use | 表前述對象**進行**後述事件　vs　表**藉由工具方法**進行後述事件 |
| 條 | Every street | 計算**行進路線**的單位　vs　計算**長條型建築或自然景觀**的單位 |

這些區分在中文裡成立，但**譯成英文之後資訊已經不在了**。要求任何評判者
（人或模型）從譯文回推，本質上是在猜。

證據：**人工 vs gold 只有 75%**。研究者是母語者、看得到原句、無時間壓力，
與 CWN 標註仍有四分之一不一致。這就是本基準在目前義項粒度下的**天花板**。

judge 的 70%（vs gold）距離該天花板只差 5pp。用 60% 這個絕對門檻評判 judge，
等於忽略了任務本身的上限。

## 5　NONE 幾乎全部是 judge 的 bug，不是設計問題

見 [`none_analysis.md`](none_analysis.md)（現為 v2；v1 的數字保留在下表）。

v1 時我一度懷疑「功能詞／量詞在英文中沒有詞彙對應」是設計層級的問題。
換上 v2 之後這個落差大幅收斂，**該懷疑不成立**：

| 詞類 | n | NONE 率 v1 | NONE 率 v2 |
| --- | :-: | :-: | :-: |
| 動詞 V* | 91 | 15% | 3% |
| 名詞 N* | 51 | 33% | 2% |
| 量詞 Nf | 36 | 39% | 6% |
| 功能詞 P/C/T/D | 22 | **50%** | 14% |
| **功能詞／量詞 vs 實詞** | | **43% vs 22%（+21pp）** | **9% vs 3%（+6pp）** |

v1 的 28% NONE 率裡，絕大部分是 A 類 bug 造成的假 NONE。
換 prompt 後整體 NONE 率 **28% → 4%**，可判定題數 144 → 191。

功能詞仍略高（14% vs 3%），但 n=22，CI 很寬，不足以支持設計調整。

## 7　200 筆基準用 v2 重跑的結果

譯文全部快取命中（未重譯，翻譯端完全相同），只有 judge 重跑。

| | judge v1 | judge v2 |
| --- | :-: | :-: |
| NONE | 56（28%） | **9（4%）** |
| 可判定 | 144（72%） | **191（96%）** |
| 義項正確率 | 0.618　[0.537, 0.693] | **0.550　[0.479, 0.619]** |
| 主流 | 0.667　n=75 | 0.582　n=98 |
| 非主流 | 0.565　n=69 | 0.516　n=93 |
| **兩層之差** | +10.1pp　[-6.0, +25.6] | **+6.6pp　[-7.8, +20.8]** |

正確率下降是預期內的：v1 把 47 題誤判成 NONE 而排除在分母外，
這些題目補回來之後多數是答錯的。**v2 的 0.550 才是比較可信的數字。**

### 兩個分析在兩版下結論一致

**主流偏好——仍然不支持。**

| | n（錯誤） | 選到最高頻 | 比率 | 95% CI | 隨機基準 | 超過隨機 |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| v1 | 55 | 12 | 21.8% | [12.9, 34.4]% | 13.4% | ❌ |
| v2 | 86 | 17 | 19.8% | [12.7, 29.4]% | 13.8% | ❌ |

錯誤樣本從 55 增至 86，結論不變：CI 下界仍低於隨機基準。
v2 的排名分布 `1:17 2:23 3:12 4:8 5:8 6:14 7:3 8:1`，眾數在第 2 名而非第 1 名。
**CHA-Gen 的「模型偏好主流解讀」在本任務的錯誤模式中沒有複現。**

**長度稽核——CI 排除 0.5 者兩版皆為 0 項。**

### 兩層之差的走勢

+22.4pp（n=30）→ +10.1pp（n=200, judge v1）→ **+6.6pp（n=200, judge v2）**

每次把測量做得更乾淨，效果就縮小一次，CI 始終涵蓋 0。
目前**沒有證據**支持「非主流義項較難翻對」。
